## In short

- **The app is sound.** Two prior audits (18 and 19 November) were built and verified; this run re-reported nothing
  they fixed, and the perf/debt auditor confirmed the fixes hold (eviction, batching, memoisation, atomic writes,
  dead-code removal — all verified in the code, listed under "rejected" below).
- **No new lost-work bug.** The strongest correctness findings are races on paths the last audit's lock fix didn't
  cover (commit/switch/update), a git-parsing bug that disables turn attribution after a merge, and wind-down paths
  that can hang on a full disk — all bounded, all with a test-first plan.
- **The security findings are gaps in guards the repo already built elsewhere:** Codex skips the destructive-command
  guard at Full (Claude/ACP honour it); a remote `http://` endpoint gets the key in cleartext; `/addon-check` reads
  64 MB before checking its token; the update's signature is checked before the waiter, not before the move; the
  turn-grant's in-project check doesn't follow symlinks (the ACP gate does). None is a remote exploit — all need
  local access, a user action, or a planted link — but each contradicts a promise the app makes in its own docs.
- **CI is red on main and has never checked this branch.** The workflow's only run ever failed on a fifth timing
  flake; the desktop steps were skipped; there is no UI build step; the branch is 12 commits ahead with no PR.
  Plan 015 is the prerequisite for everything else's release gate.
- **The polish layer has ~20 detail faults**, all new beyond the layout backlog: a push card that claims one commit
  when git pushed zero, a held shortcut that drains the queue, failed reads that render as empty, seven tablists and
  eight radio groups without the arrow keys the app teaches elsewhere, three spinners that ignore Reduce Motion,
  storage reads that break a storage-less window at mount. All 20 are planned (016–021).
- **The biggest remaining feel cost:** the open session's own stream still redraws the whole dock every frame
  (~1,154 redraws/6 s in the 11-18 audit's own post-fix measurement) — an inline JSX prop defeats the memoisation
  that pass built. Plan 027, measure-first.

## Direction — where to take it next (grounded options, the owner's call)

1. **Restore the two-pane dock, or delete its rules.** `dock.ts:11`: nothing has made a second pane since 0.2.2, yet
   L06/L13 kept fixing rules nobody can reach. The dock kit's split/moveTab and the CSS exist — a drag-to-edge split
   is one interaction away (the adjacent possible). Trade-off: revive a feature unused for eight versions vs delete
   ~100 dead lines. Spike it in the measuring build first; the layout README records it as the owner's call.
2. **⌘K across sessions, with an index.** `docs/T3CODE.md`: "No search over session contents in ⌘K yet";
   `sessions.search` exists (`api.ts:1235`), agents already have `sessions_search`, and CORE-08 found the search
   reads whole histories synchronously. Wiring ⌘K to it plus a small FTS index delivers the ROADMAP's stated
   direction ("search past sessions (SQLite FTS)") and fixes the stall together. Trade-off: an index is a new store
   dependency; Node 24's `node:sqlite` or a small inverted index are the cheap shapes.
3. **A screenshot of the picked Browser element.** ROADMAP "Next", undelivered; the offscreen-capture machinery
   already exists for designs and hidden Browsers. The pick card sends HTML only today — pixels alongside it is one
   capture call away. Trade-off: capture cost per pick; the agent gets something it can reason about visually.
4. **PR review comments on the diff's lines, and link-by-URL.** ROADMAP "Next", undelivered; the Reviewer's findings
   already render on lines and `gh` is wired. Reuse that rendering for GitHub's own review comments; a link-by-URL
   input attaches any PR to a session. Trade-off: gh rate limits and comment threading.
5. **Record tested CLI versions; warn on drift.** The Cursor/Grok drivers have never been run, the SDK is 19 patches
   behind, and PROV-01 shows the approval contract can silently break per-tool. The updater already knows every
   version; recording the tested ones and warning quietly on drift protects the contract. Trade-off: warn-vs-block
   is a product decision (the plans README records it); warning fatigue is real.

### [CORE-01] Read a merge commit's parent line as parents plus a timestamp, not two words

- **Evidence**: `engine/src/checkpoints.ts:227-231` — `git log --no-walk=unsorted --format=%P %ct` is split with `fromLine.split(" ")` into `[start, at]`; a merge commit prints two parents, so `at` becomes the second parent's hash, not the commit time. `engine/src/checkpoints.ts:244` — `--since=@${at}` then fails to parse, `list()` throws (`:235`), and the catch at `:248-251` returns null, which `changes()` (`:206`) reads as "HEAD stayed put, every change is the turn's".
- **Impact**: When HEAD was a merge commit at the turn's start and moved during the turn (a pull or merge mid-turn), the authored-paths filter silently disables itself: files the pull brought in are attributed to the turn, so its diff card shows them and Undo puts back files the turn never wrote. The fallback comment says "an older git without remerge diffs", but this fires on current git too.
- **Effort**: S
- **Risk**: LOW — parsing change only; the null fallback stays for genuine failures.
- **Confidence**: MED — read the code; git's `%P` output for merges is certain, the end-to-end effect needs a scratch-repo test (a merge at turn start, HEAD moved during it).
- **Fix sketch**: Separate the fields unambiguously (`--format=%P%x09%ct`, take the last tab-field as the time, the first parent as start), and add a test with a merge-commit HEAD that fails without the fix.

### [CORE-02] Ask git for the Reviewer's small-change numstat with -z and -M, as the checkpoint path does

- **Evidence**: `engine/src/runtime.ts:1860` — `changeOf` runs `git diff --relative --numstat from cp.to` with neither `-z` nor `-M`; `contracts/src/index.ts:1194-1199` (`smallChange`) then tests `f[2]` against `/\.(md|mdx|txt|rst|adoc)$/i`. Without `-z`, git C-quotes a non-ASCII path (`"caf\303\251.md"`), so the trailing quote defeats the docs test; without `-M`, a rename reads as delete+add with full line counts. The checkpoint path already knows this (`engine/src/checkpoints.ts:160-164` comment, `-M -z` at `:187`).
- **Impact**: A docs-only change with one non-ASCII file name, or a pure rename of a large file, is never "small": it costs a full Reviewer read (a quiet model turn, up to 10 minutes) instead of passing through. Wasted spend and wait, no lost work.
- **Effort**: S
- **Risk**: LOW — same flags the diff card already uses; smallChange's parser would need the -z record shape (or keep -M only and strip quotes).
- **Confidence**: HIGH — git's quoting without -z is documented and already cited in checkpoints.ts; the regex mismatch is plain in the code.
- **Fix sketch**: Pass `-z` (and `-M`) and parse records as `numstat()` does, or at minimum `-M` plus unquoting; test a unicode docs-only change and a rename that reads small without the fix being absent.

### [FEAT-01] Cap frame-file reads on the watcher and open paths, as the tool paths already do

- **Evidence**: `engine/src/canvas.ts:1161` — `changedOnDisk` does `readFileSync(abs)` on any changed file under a watched design folder with no size check, then `hash(content)` (sha1) at 1171/1192. `engine/src/canvas.ts:2136` — `revsOf` (canvas.open) reads every drawn frame file whole, no `MAX_FRAME` check. `engine/src/designs.ts:216` — `Designs.read` reads the live design file with no size cap (show() enforces 2 MB at 168, read() does not). Contrast `frameFile()` at `canvas.ts:980` which refuses >2 MB.
- **Impact**: An agent (or a bad edit) writing a huge file into `frames/` — e.g. a base64 video inline, the exact case MAX_FRAME exists for — makes the engine read the whole file and sha1 it on its single thread inside a watcher callback, and canvas.open repeats it per frame. Memory spike plus a multi-hundred-ms stall of every session's stream; the 2 MB guard is bypassed on precisely the paths that run automatically.
- **Effort**: S
- **Risk**: LOW — a size refusal where reads already refuse elsewhere; watcher must still emit the change (with no rev) so the UI learns the file is unreadable.
- **Confidence**: HIGH
- **Fix sketch**: In `changedOnDisk` and `revsOf`, stat first and skip the read/hash above MAX_FRAME (emit the event without a rev, as a gone file does); add the same cap to `Designs.read`. Test: a 3 MB frame file changed on disk produces a canvas.changed without stalling or reading it whole.

### [FEAT-02] Keep a turn's provisional copy when the next turn begins before its end work runs

- **Evidence**: `engine/src/canvas.ts:1791-1793` — `beginTurn` synchronously drops the previous look's provisional copies (`dropProvisional`). `engine/src/canvas.ts:2085-2098` (attach) — `beginTurn` runs inline on the turn-start event, but `turnEnded` for the previous turn is only queued (`queue(ctx, …)`), and it awaits `digestAsync` before promoting. `promote` at 1673 silently returns when the `p<turn>` dir is gone.
- **Impact**: In a session not known to draw (a Code session whose agent edits a design), sending the next message promptly after the previous turn ends deletes the "as it was" copy before `turnEnded` can promote it; `keepVersionAsync` then copies the *current* state, so the pre-turn state of that turn is lost from Versions and cannot be brought back. The comment at 1790 treats this as the engine-restart case, but the same drop fires on ordinary fast turn succession.
- **Effort**: M
- **Risk**: MED — version lifecycle is delicate (promote/drop/prune interact); needs a characterization test of two overlapping turns first.
- **Confidence**: MED (code path is certain; the timing window needs a test to pin down)
- **Fix sketch**: Don't drop the previous look's provisionals in beginTurn; hand them to the queued turnEnded (or mark them superseded and let turnEnded decide), dropping only copies whose turn's end has already been processed. Test: turn N changes a design, turn N+1 starts before N's end work runs, N's "as it was" copy survives.

### [FEAT-03] Take canvas.restore's "before" copy and file puts off the engine loop

- **Evidence**: `engine/src/canvas.ts:1715-1716` — `keepBefore` does `cpSync(src, to, { recursive: true, … })` (a plain byte copy, no FICLONE) plus sync `digest(ctx, src)` hashing every file. `engine/src/canvas.ts:2044-2059` — restore's `put` loop reads and writes every copied file synchronously. Turn copies were moved off-loop (`keepVersionAsync`, `digestAsync`, `takeProvisional`), restore was not.
- **Impact**: Restoring a version of a design with a few MB of assets blocks the engine's single thread for the whole copy+hash+rewrite — every session's streaming, terminals and RPCs stall while the person scrubs Versions. This is the residual of the C-class sync-work fixes the brief asks to look for.
- **Effort**: M
- **Risk**: LOW-MED — restore must stay atomic-ish (keepBefore before any deletion); the async rewrite can reuse cloneDesign/slowCopy and the existing queue.
- **Confidence**: HIGH
- **Fix sketch**: Make restore async: keepBefore via cloneDesign (FICLONE where possible) + digestAsync, put loop via fs/promises, all on the session's queue; canvas.restore already awaits canvasIdle, so awaiting the rest is natural. Test: a restore of a folder with a large asset yields to the loop (a timer fires mid-restore).

### [FEAT-04] Yield inside a panel's files.search instead of scanning the project synchronously

- **Evidence**: `engine/src/panels.ts:150-178` — the search loop over `listFiles(root, 20000)` is fully synchronous: per file `readable()` (two `realpathSync`), `statSync`, `readFile` (sync readFileSync up to 512 KB), split and scan; it only stops at the match limit or 20 MB read. A query with few matches walks all 20k files without a single await.
- **Impact**: One panel search in a large project holds the engine thread for seconds (realpath×2 + stat + read per file), stalling every session's stream and RPC — the same class the 11-18 audit fixed for checks ("a big repository never holds the engine's thread for long"), left in the panel bridge.
- **Effort**: M
- **Risk**: LOW — semantics unchanged; only interleaving added.
- **Confidence**: HIGH
- **Fix sketch**: Process files in chunks (e.g. 200) with `await new Promise(setImmediate)` between chunks, keeping the existing limits; reuse one realpath of the root. Test: a search over a fixture of many files lets a concurrent timer/RPC run mid-search.

### [FEAT-05] Give the simulator screenshot a timeout and drain its stderr

- **Evidence**: `engine/src/surfaces.ts:699-707` — `screenshot` spawns `xcrun simctl io … screenshot` with no timeout; the promise settles only on `close`/`error`. stderr is a pipe nobody reads. Contrast `devices()` at 680 which uses `run` with `timeout: 20000`.

- **Effort**: S
- **Risk**: LOW — a timeout rejects with the same sentence the close-path already uses.
- **Confidence**: HIGH
- **Fix sketch**: Race the close against a ~20 s timer that kills the child and rejects; attach a stderr drain (or stdio ignore for stderr). Test: a fake xcrun that never exits rejects within the timeout.

### [FEAT-06] Escape the Device log filter for NSPredicate, and say when the stream dies

- **Evidence**: `engine/src/surfaces.ts:728` — the filter is embedded in `eventMessage CONTAINS[c] "…"` with only `"` stripped; a backslash is not escaped, so a filter ending in `\` escapes the closing quote and the predicate is malformed. `engine/src/surfaces.ts:729-734` — the spawned `log stream`'s stderr is unread and its exit is only removed from the map; nothing tells the app the stream failed.

### [SEC-01] Endpoint and add-on keys reach spawned processes through the environment, where anything running as you can read them

- **Evidence**: `engine/src/providers/endpoint.ts:45` — third-party endpoint key set as `ANTHROPIC_AUTH_TOKEN` in the spawned Claude Code process env; `engine/src/providers/endpoint.ts:64,71` — same key as `LINER_ENDPOINT_KEY` in Codex/OpenCode env. `engine/src/addons.ts:826-830` — add-on connection secrets filled into spawned MCP servers' env. Contrast `engine/src/agent-tools.ts:310-319`, which moved the session key to a 0600 file precisely because "an environment and a command line can be read by anything running as you (ps eww), a sandboxed plugin included". `SECURITY_MODEL.md:10` states secrets "are not passed on to anything it spawns" — the code passes these keys on, in env.
- **Impact**: Any same-user process — including a sandboxed DSH plugin, whose sandbox allows reading process info — can harvest third-party API keys and add-on secrets from the env of running agent tools/MCP servers with `ps eww`. The session-key fix (plan 004) closed this hole for surface keys but left the larger-value keys (API keys are "equally critical" assets per SECURITY_MODEL.md) exposed. Also decision-drift: the threat model's shell↔engine bullet claims spawned processes get no secrets.
- **Effort**: M — pass endpoint/add-on keys via a per-session 0600 file or stdin handoff where each tool supports it (Codex env_key and OpenCode {env:…} read env by design, so some tools need a wrapper or a documented exception); update SECURITY_MODEL.md to say exactly which keys go where.
- **Risk**: MED — each agent tool reads its key differently; a wrong handoff breaks endpoint sessions. Needs the real-tool run the release rules already require.
- **Confidence**: HIGH (code read; exposure mechanism is the one the repo itself documents at agent-tools.ts:310).
- **Fix sketch**: Extend the plan-004 key-file pattern to endpoint and add-on keys where the tool can read a file/stdin; where a tool only accepts env, record that exception explicitly in SECURITY_MODEL.md and the ROADMAP open item instead of the blanket "not passed on" claim.

### [SEC-02] The update's signature is re-verified before the waiter script starts, not right before the swap

- **Evidence**: `desktop/src/update.ts:53-61` — `install()` calls `staged()` (which runs codesign/Team-ID checks via `desktop/src/signed.ts:39-59`), then spawns a bash script; `desktop/src/update.ts:40-45` (SCRIPT) — the script waits up to 60 s for the app to exit and only then `mv`s the bundle into place. `SECURITY_MODEL.md:20` says the shell checks the signature "again right before it swaps the bundle in".
- **Impact**: A same-user local process (attacker profile 1 in the threat model) with write access to `~/.liner-code/updates` can replace the verified bundle during the verify→exit→mv window (tens of seconds, plus however long the user takes to quit), and the swap installs the replacement as the app. The script also strips quarantine (`update.ts:47`), so Gatekeeper's first-launch assessment never runs on what was swapped in. The re-verification built in plan 010 covers download→swap tampering at rest, but not this race.
- **Effort**: M — re-run `signedAsOurs` inside the swap script immediately before `mv` (codesign is available to bash), or verify-and-move atomically via a hardlink/rename of a just-verified copy; add a desktop test that swaps the staged bundle after verification and expects refusal.
- **Risk**: LOW — the check already exists; moving it later in the sequence only adds a refusal path.
- **Confidence**: MED (race read from code; needs a local writer to exploit, and the ad-hoc-trust open item already accepts a weaker baseline for unsigned copies).
- **Fix sketch**: Verify in the script right before the move (fail → swap-failed.txt), and correct SECURITY_MODEL.md's "right before" wording to match wherever the check lands.

### [SEC-03] /addon-check call and report read the whole body before checking the token

- **Evidence**: `engine/src/server.ts:208-214` — `/addon-check/<tok>/call` and `/report` do `await body(req)` (up to 64 MB, `server.ts:98`) and only then look the token up in `checkCall`/`checkReport` (`engine/src/agent-tools.ts:864-866,887-889`). Contrast `engine/src/server.ts:168-169`: /surface and /outside check the key first, with the comment "a caller without one isn't worth 64 MB of reading".
- **Impact**: Any web page (simple POST, no preflight needed for text/plain) or local process can make the engine buffer up to 64 MB per request against invented 36-hex tokens, with no rate limit — memory pressure / slow-body DoS on the engine that drives the user's agents. The same guard the repo built for the other keyless routes is missing here.
- **Effort**: S — add a `knows.check(token)` pre-check (the checks map already exists) before reading the body, mirroring the surface/outside path; test that an unknown token is refused without a body read.
- **Risk**: LOW — mirrors an existing, tested pattern.
- **Confidence**: HIGH.
- **Fix sketch**: Extend the `knows` hook with a check-token predicate and refuse unknown tokens before `body(req)` on call/report (settle/page are GET and already cheap).

### [SEC-04] The Browser proxy strips the dev server's CSP and X-Frame-Options from every page
